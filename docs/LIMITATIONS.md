# 구현 범위와 확장 과제

공모전 시연용 MVP의 업무 흐름은 구현되어 있다. 아래 외부 연동은 모의 처리이며, 실서비스 운영을 위한 인증·저장·복구 기능과 구분한다.

| 구분             | 현재 동작                               | 실서비스 확장                          |
| ---------------- | --------------------------------------- | -------------------------------------- |
| 예매처           | 같은 서버를 별티켓·달티켓 프로필로 실행 | 실제 예매처 API 연동                   |
| 결제·환불·정산   | 모의 API 호출과 로그로 절차 확인        | PG 연동, 거래 기록 테이블, 대사        |
| 본인인증·로그인  | 데모 계정 선택, 고정 인증번호 `123456`  | 실제 로그인 세션, 본인인증 사업자 연동 |
| 관리자·입장 화면 | 별도 로그인 없이 실행                   | 역할별 인증·권한 검사                  |
| 데이터베이스     | H2 인메모리, 재시작 시 초기화           | 영속 DB, 백업·복구                     |
| IP 분류          | 시연용 IP 대역 목록                     | 유지되는 IP DB 연동                    |
| 기기 식별        | 브라우저 저장소의 ID를 해시해 비교      | 신뢰 가능한 기기 검증 및 복구 정책     |

## 장애 처리의 범위

- 재발급 실패 시 환불·한도 반환·판매자 권한 복원, 응답 유실 시 같은 멱등키로 재시도하는 시나리오를 제공한다.
- 멱등키 응답 저장과 업무 처리가 하나의 트랜잭션으로 묶여 있지 않다. 업무 처리 직후 응답 저장 전에 중단되면 재시도 결과를 안전하게 복구하지 못할 수 있다. 원자적 저장과 복구 절차가 확장 과제다.
- 재판매 서비스는 DB 트랜잭션 안에서 예매처를 동기 호출한다. 네트워크 지연 시 트랜잭션이 길어질 수 있다. 별도 작업 큐·아웃박스·보상 작업 도입은 이후 설계 과제이며, 현재 리팩터링에서 처리 순서는 바꾸지 않는다.
- 로컬 설정은 데모 모드와 H2 콘솔을 켜고 개발용 키를 사용한다. 운영 배포에는 별도 프로필, 비밀키 관리와 접근 제어가 필요하다.

## 구현 완료된 인증·검증 시나리오

위험 등급별 추가 인증, 재판매 자동 기한 처리, QR 카메라 스캔, 동적 QR 검증, 기기 이전 제한, 서버 간 요청 서명은 구현되어 있다. 외부 인증·결제 연동과는 구분한다.
