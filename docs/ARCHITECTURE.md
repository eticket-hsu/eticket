# 구조와 연동 규약

별티켓·달티켓은 가상 예매처이며, 발행·무효화·입장 판단은 예매처 서버가 담당한다. eTicket은 공통 구매 한도, 위험 분석과 공식 재판매 절차를 연결한다.

## 주요 API

| 서버    | 경로                                                                                                                     | 용도                                                                                                  |
| ------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| eTicket | `POST /v1/quota/reserve`, `/v1/quota/{id}/confirm`, `/v1/quota/{id}/release`, `GET /v1/quota`                            | 공통 구매 한도: 결제 전 예약 → 발급 시 확정 / 실패 시 즉시 반환                                       |
| eTicket | `POST /v1/resales`                                                                                                       | 재판매 등록 (가격 상한을 발행처에 조회해 검증, 발행처 잠금까지)                                       |
| eTicket | `GET /v1/resales`, `GET /v1/resales/{id}`                                                                                | 목록, 상세(응모자·이력)                                                                               |
| eTicket | `POST /v1/resales/{id}/entries`                                                                                          | 응모 (판매자 본인·중복·HIGH 위험 제외)                                                                |
| eTicket | `POST /v1/resales/{id}/draw` · `/forfeit` · `/pay`                                                                       | 추첨, 차순위 이전, 결제→재발급→정산                                                                   |
| eTicket | `DELETE /v1/resales/{id}`                                                                                                | 판매 전 취소                                                                                          |
| eTicket | `POST /v1/purchase-events`, `GET /v1/risk`, `GET /v1/risk/overview`                                                      | 위험 분석 (실시간)                                                                                    |
| eTicket | `POST /v1/demo/purchase-events`, `GET /v1/demo/risk`, `GET /v1/demo/review`                                              | 시연 도구·시뮬레이터·비교 실험용 (시연 모드에서만 열림). `vendorId` 를 주면 그 예매처 기록만으로 판단 |
| eTicket | `GET /v1/risk/review?performanceCode=`, `POST /v1/risk/review/reports`                                                   | 사후 검토·계정 묶음, 발행처 전달                                                                      |
| eTicket | `POST /v1/risk/review/cancel`, `GET /v1/risk/review/cancellations`                                                       | 의심 계정 표 취소 요청(발행처가 취소) · 취소 기록                                                     |
| eTicket | `GET /v1/captcha`, `POST /v1/captcha/verify`                                                                             | 예매처에 제공하는 공통 보안문자 (1회용)                                                               |
| eTicket | `POST /v1/verify`, `GET /v1/verify/logs`                                                                                 | 입장 검증 중계                                                                                        |
| 예매처  | `GET/POST /api/*`                                                                                                        | 예매처 사이트용 (회원, 공연, 구매, 내 티켓, 재판매 신청)                                              |
| 예매처  | `POST /api/tickets/{id}/device`                                                                                          | 본인인증 후 표를 이 기기로 옮기기 (요청 헤더 `X-Device-Id`)                                           |
| 예매처  | `/ft/tickets/{id}` · `lock` · `unlock` · `reissue` · `fraud-cancel`, `/ft/admit`, `/ft/payments` · `refunds` · `payouts` | 발행처 표준 API                                                                                       |

**서버 간 인증이 필요한 API** (아래 '연동 규약' 참고): 예매처 `/ft/*` 전체, eTicket 의 `POST /v1/purchase-events`, `GET /v1/risk`, `POST /v1/captcha/verify`, `POST /v1/quota/reserve` · `{id}/confirm` · `{id}/release`, `POST /v1/resales`.

## 구현된 업무 규칙

- **공통 구매 한도:** 한도 값은 발행처가 정하고(예매처마다 다르면 작은 값), eTicket 은 연동 예매처 구매를 사람·공연 단위로 합산. 예약 유효시간은 예매처의 결제 제한 시간(별티켓 10분, 달티켓 8분). 결제 실패·재발급 실패는 즉시 반환, 재판매로 산 티켓도 포함, 판매자는 재발급 완료 시 반환
- **재판매 가격:** 상한 = min(정가, 현재 소유자 취득가), 낮게 부르는 것은 허용. 재발급 때 거래 가격이 새 소유자의 취득가가 됨
- **수수료:** 이용자 수수료 없음
- **기한:** 신청 마감·판매 종료·결제 기한은 발행처가 공연별로 정하고, 없으면 기본값(신청 마감 공연 6시간 전 / 판매 종료 3시간 전 / 결제 30분). 기한이 지나면 스케줄러가 차순위 이전·추첨·만료 처리
- **구매자 선정:** 공연 24시간 전까지 추첨, 그 뒤 선착순(바로 구매). 추첨 응모자가 없거나 당첨자가 모두 결제하지 않으면 판매 종료 전까지 선착순으로 전환. `eticket.resale-defaults.selection: LOTTERY`로 바꾸면 추첨만 사용
- **위험 분석 기본 규칙 8개:** 요청 빈도(+20), 기계적 간격(+25), 반응 시간(좌석 화면 진입 후 0.5초 미만 또는 화면 없이 요청, +25), 교차 예매처(+20), 한도 초과 시도 반복(+20), 반복 실패(보안문자 오답 포함, +20), IP 공유(보조, +10), 기기 공유(10분 안에 한 기기에서 3개 계정 이상, +20). 기기 정보 없이 API 로 바로 부른 구매는 실패로 센다. 0~39 정상 / 40~69 주의 / 70+ 고위험
- **등급별 조치:** 정상 허용 / 주의 보안문자 / 고위험 보류(보안문자 + 본인인증으로 해제). 보안문자는 eTicket 이 예매처에 제공하는 공통 서비스(`/v1/captcha`), 본인인증은 시연용 모의(인증번호 123456). 통과 후에도 분석은 계속
- **재판매 응모:** 주의는 보안문자 후 응모, 고위험은 응모 불가
- **사후 검토:** 공연 전체 기록에서 신호 2개 이상 겹친 사용자 + 여러 예매처에 걸친 계정 묶음(IP만 같은 PC방 손님은 제외)을 발행처에 전달
- **멱등키 (`Idempotency-Key`):** eTicket 은 상태를 바꾸는 `/ft/*` 호출마다 `resale-{id}-{동작}` 키를 붙이고 재시도해도 같은 키를 쓴다. 발행처(`IdempotencyFilter`)는 키 없는 요청을 400 으로 거절하고, 처음 보는 키는 처리 후 응답을 저장, 같은 키는 다시 처리하지 않고 저장된 응답을 돌려준다(`Idempotent-Replayed: true`). 같은 키에 내용이 다르면 422, 동시에 오면 1건만 처리, 5xx 는 저장하지 않아 재시도 가능, 24시간 보관. 입장 처리(`/ft/admit`)는 원래 한 번만 성공하므로 제외
- **서버 간 인증 (요청 서명):** 비밀키는 보내지 않고 HMAC-SHA256 서명만 보낸다. 헤더 `X-FT-Client`·`X-FT-Timestamp`·`X-FT-Nonce`·`X-FT-Signature`, 서명 대상은 메서드·경로+쿼리·시각·난수·멱등키·본문 해시. 받는 쪽은 등록된 호출자인지, 시각이 ±5분 안인지, 서명이 맞는지(시간 일정 비교), 난수가 처음인지(재전송 차단) 확인하고 아니면 401. 키는 방향별·예매처별로 따로(FT→별, 별→FT, FT→달, 달→FT), 환경변수로 넣고(설정 파일엔 로컬용 기본값만), 받는 쪽은 키 목록을 받아 교체 중 옛 키·새 키를 함께 허용. eTicket 은 본문의 `vendorId` 대신 서명으로 확인된 예매처를 기록하고, 다르면 403(다른 예매처 이름 사칭, 남의 한도 예약 확정·반환 차단)
- **계속 바뀌는 QR (캡처 QR 무효):** QR 은 `FT:{발행처}:{티켓}:{버전}:{시간칸}.{서명}`, 시간칸은 30초 단위. 입장은 지금 칸만 받고 바로 앞 칸은 칸이 바뀐 뒤 10초까지만 받아서, 캡처·인쇄한 QR 은 길어야 40초 뒤 "만료된 QR"로 거절된다. 시간칸을 고쳐 쓰면 서명이 맞지 않아 위조로 거절 (티켓마스터 SafeTix 와 같은 방식)
- **기기 묶기:** 표는 예매한 기기에 바로 묶여 그 기기에서만 QR 이 보이고, 다른 기기에서는 QR 대신 "다른 기기"가 뜬다. 기기 정보 없이 API 로 바로 사는 요청은 거절한다 (묶이지 않은 표를 계정째 넘겨 받는 사람 폰에 묶이게 하는 수법 차단). 폰을 바꾼 주인은 본인인증 후 옮길 수 있지만 공연 24시간 전부터는 못 옮긴다 (`vendor.device-move-cutoff-hours`, 현장 신분증 확인으로 처리). 기기 ID 는 해시로만 저장. 2번 이상 옮기면 사후 검토에 "표를 다른 기기로 옮김" 신호
- **같은 기기 여러 계정:** 예매처가 기기 해시를 eTicket 에 함께 보낸다. 한 기기에서 여러 계정이 사거나, 여러 계정의 표가 한 기기로 옮겨지면(암표상이 본인인증 번호를 전달해 주는 계정 넘기기 거래) 사후 검토에 "같은 기기를 쓴 계정" 신호가 붙고 계정 묶음으로 이어진다
- **의심 표만 신분증 확인:** 사후 검토 의심 목록에 있는 사람의 표는 입장 화면에 "신분증 확인"과 예매자 이름(가운데 가림)을 띄운다. 모든 관객을 확인하면 줄이 길어지므로 의심 표만
- **IP 검사:** 접속 IP를 내부망·일반·해외·VPN·데이터센터·Tor 로 판별해 위험 점수에 더한다 (VPN +25, 데이터센터 +25, Tor +40, 해외 +10). 브라우저 시간대는 한국인데 IP가 해외·VPN이면 시간대 불일치 +15. 원래 IP는 저장하지 않고 종류만 남긴다. 해외 거주 팬 오탐을 줄이려고 해외 IP 단독으로는 막지 않는다. `eticket.ip-policy.block-anonymous: true`로 바꾸면 VPN·데이터센터·Tor 예매를 바로 보류한다(인터파크식 차단). IP 목록은 `eticket-server/src/main/resources/ip-ranges.csv` (시연용 문서 전용 대역, 실서비스는 상용 IP DB·공식 목록으로 교체)
- **탐지 → 조치 (부정 구매 취소):** 사후 검토의 의심 계정(신호 2개 이상) 중 발행처 담당자가 고른 계정의 표만 취소 요청한다. 발행처가 표를 취소·환불하고, 그 표는 입장 검증에서 "부정 구매로 취소된 티켓"으로 거절된다. 취소한 만큼 공통 구매 한도를 돌려주고, 취소 근거(겹친 신호)를 기록으로 남긴다. 의심 목록에 없는 계정은 요청해도 취소하지 않는다
- **시연 전용:** 한 노트북에서 여러 사람을 흉내 내므로 로컬 접속은 회원별 가상 IP 를 쓴다. `eticket.demo-mode` 는 실서비스에서 끈다

## 이름과 호환성

서비스 이름은 eTicket, 서버 폴더는 `eticket-server`, Java 패키지는 `com.eticket`이다. Java 클래스는 `ETicket` 접두사를 쓴다.

기존 연동 규약인 `/ft/*`, `X-FT-*`, `FT:` QR 접두사, `ft-u-*` 데모 식별자, 브라우저 저장소 키는 유지한다. 이 값들은 표시 이름이 아니라 서버와 클라이언트가 공유하는 규약이다.

환경변수는 `ETICKET_TO_STAR_SECRET`, `STAR_TO_ETICKET_SECRET`, `ETICKET_TO_MOON_SECRET`, `MOON_TO_ETICKET_SECRET`을 사용한다. 이전 이름으로 설정한 환경은 새 이름으로 갱신해야 한다. 서버 설정 접두사는 `eticket`, 예매처의 서버 주소 설정은 `vendor.eticket-url`이다.
